================================================================================
PLANO — MULTI-USUÁRIO (Multi-Tenancy) — Consultório
================================================================================

OBJETIVO
Cada usuário (Marcelo, sogra, etc.) enxerga APENAS os próprios dados.
Sua sogra vê os pacientes dela, você vê os seus.

PADRÃO ESCOLHIDO: coluna `usuario_id` em cada tabela (multi-tenancy)
É o mesmo modelo usado por WhatsApp, Uber, Instagram e sistemas de clínica
profissionais. Não criar tabelas separadas por usuário.

--------------------------------------------------------------------------------
1. DESEMPENHO (dúvida das 1.000.000 de linhas)
--------------------------------------------------------------------------------
Risco: "WHERE usuario_id = X" em 1M de linhas ficar lento?
SOLUÇÃO: ÍNDICE no banco.

    CREATE INDEX idx_consultas_usuario  ON "Consultas" (usuario_id, data);
    CREATE INDEX idx_pacientes_usuario  ON "Pacientes" (usuario_id);
    CREATE INDEX idx_orcamentos_usuario ON "Orcamentos" (usuario_id);

Com índice (árvore binária), o Postgres encontra as linhas de um usuário em
MILISSEGUNDOS, sem varrer a tabela. 1M de linhas é "nada" para Postgres.
Mesmo padrão que escala para BILHÕES de linhas em apps grandes.

------------------------------------------------------------------------------
2. QUais TABELAS recebem `usuario_id`
------------------------------------------------------------------------------
Pacientes    -> SIM  (dado por usuário)
Consultas    -> SIM  (agendamento por usuário)
Orcamentos   -> SIM  (financeiro por usuário)
Usuarios     -> NÃO  (é a própria tabela de usuários)
Tratamentos  -> SIM  (cada usuário tem sua lista de serviços/preços) [DECIDIDO]

------------------------------------------------------------------------------
3. BANCO (Supabase) — SQL a rodar
------------------------------------------------------------------------------
IMPORTANTE: no PostgreSQL nomes de tabela com letra maiúscula exigem ASPAS DUPLAS.
As tabelas deste projeto chamam-se "Pacientes", "Consultas", etc.

    ALTER TABLE "Pacientes"   ADD COLUMN usuario_id INTEGER REFERENCES "Usuarios"(id);
    ALTER TABLE "Consultas"   ADD COLUMN usuario_id INTEGER REFERENCES "Usuarios"(id);
    ALTER TABLE "Orcamentos"  ADD COLUMN usuario_id INTEGER REFERENCES "Usuarios"(id);
    ALTER TABLE "Tratamentos" ADD COLUMN usuario_id INTEGER REFERENCES "Usuarios"(id);

    CREATE INDEX idx_consultas_usuario   ON "Consultas"   (usuario_id, data);
    CREATE INDEX idx_pacientes_usuario   ON "Pacientes"   (usuario_id);
    CREATE INDEX idx_orcamentos_usuario  ON "Orcamentos"  (usuario_id);
    CREATE INDEX idx_tratamentos_usuario ON "Tratamentos" (usuario_id);

    -- MIGRAÇÃO dos dados existentes: tudo vira do usuário Marcelo (id 3)
    UPDATE "Pacientes"   SET usuario_id = 3 WHERE usuario_id IS NULL;
    UPDATE "Consultas"   SET usuario_id = 3 WHERE usuario_id IS NULL;
    UPDATE "Orcamentos"  SET usuario_id = 3 WHERE usuario_id IS NULL;
    UPDATE "Tratamentos" SET usuario_id = 3 WHERE usuario_id IS NULL;
