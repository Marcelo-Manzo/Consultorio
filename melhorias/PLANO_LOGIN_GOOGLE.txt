================================================================================
PLANO - LOGIN COM GOOGLE (OAuth 2.0 / PKCE) - Consultorio
================================================================================

OBJETIVO
Permitir login na tela de acesso usando a conta Google do usuario, alem do
login por e-mail + senha que ja existe.

Decisoes ja tomadas:
  - OAuth REAL com o Google (fluxo PKCE, abre o navegador do usuario)
  - Se o e-mail do Google nao existir no banco -> CRIA o usuario automaticamente
  - Ainda NAO temos Client ID -> Passo 1 ensina a criar no Google Cloud Console

POR QUE NO DESKTOP E DIFERENTE DA WEB
Um site pode receber o redirecionamento do Google direto na URL. Um app
desktop nao tem isso. O padrao e:
  1. App abre o NAVEGADOR na tela de consentimento do Google
  2. Usuario autoriza -> Google redireciona para http://localhost:<porta>
     com um "code" na query string
  3. O App sobe um mini servidor local (loopback) que captura esse "code"
  4. O App troca o "code" por um id_token (JWT) usando o client_secret
  5. O App le o e-mail/nome do id_token e autentica (ou cria) o usuario

Isso usa o tipo de Client ID "Desktop app", que dispensa HTTPS local e aceita
http://localhost (loopback). Um Client ID "Web" NAO serve para desktop.

    - O .env NAO vai para o git (confira o .gitignore). Nunca cole essas
      credenciais em codigo.

    OBS: o "client_secret" de um app Desktop nao e um segredo forte (ele viaja
    com o binario), mas ainda assim nao deve ser commitado.

[ ] Passo 3.2 - Criar database/google_auth.py (modulo novo)
    Responsabilidade: TODO o fluxo OAuth. Nenhuma tela conhece detalhes.

    Funcoes:
      - google_configurado() -> bool
            Retorna False se GOOGLE_CLIENT_ID/SECRET nao estiverem no .env,
            para a tela poder esconder/mostrar o botao.

      - autenticar_com_google() -> dict | None
            Executa o fluxo completo (abre navegador, espera o code, troca
            por token, valida o id_token) e devolve:
                {"sub": "...", "email": "...", "nome": "..."}
            Retorna None se o usuario cancelar/fechar o navegador.

            Esqueleto (google-auth-oauthlib):

                from google_auth_oauthlib.flow import InstalledAppFlow

                flow = InstalledAppFlow.from_client_config(
                    {
                        "installed": {
                            "client_id": CLIENT_ID,
                            "client_secret": CLIENT_SECRET,
                            "auth_uri": "https://accounts.google.com/o/oauth2/auth",
                            "token_uri": "https://oauth2.googleapis.com/token",
                            "redirect_uris": ["http://localhost"],
                        }
                    },
                    scopes=["openid", "email", "profile"],
                )
                creds = flow.run_local_server(port=0)
                # creds.id_token -> JWT; o lib do google ja valida a assinatura
                # e a expiracao. Leia o claim "sub"/"email"/"name".

            Detalhes:
            - run_local_server(port=0) sobe um servidor loopback em porta
              aleatoria e captura o redirecionamento. Nao precisa registrar
              porta fixa nem URI no Console (Desktop app aceita loopback).
            - A biblioteca valida o id_token automaticamente. Ainda assim,
              confira que o "aud" bate com o CLIENT_ID.

      - obter_ou_criar_usuario(dados_google) -> Usuario
            Regra combinada (cria automaticamente):
              1. Procura por google_sub == dados["sub"]  -> se achar, retorna
              2. Senao, procura por email == dados["email"]
                 - se achar, VINCULA (grava google_sub nesse usuario) e retorna
              3. Senao, create_user_google(nome, email, sub) e retorna

[ ] Passo 3.3 - Adicionar funcoes em database/usuarios.py
    - create_user_google(nome, email, google_sub):
        cria Usuario SEM senha (senha_hash=None)
    - get_user_by_google_sub(google_sub):
        db.query(Usuario).filter(Usuario.google_sub == google_sub).first()
    - vincular_google(user_id, google_sub):
        grava o google_sub num usuario que ja existia (login por senha)
    - Exportar as novas funcoes em database/__init__.py (imports + __all__),
      seguindo o padrao do arquivo.

--------------------------------------------------------------------------------
RISCOS / OBSERVACOES
--------------------------------------------------------------------------------
- App em modo Testing: so "Test users" entram. Cadastre cada pessoa que for
  usar, ou publique o app (Production).
- Nada de senha no Google: usuario so-Google nao loga pela tela de senha ate
  definir uma.
- O fluxo abre navegador externo; se a maquina nao tiver navegador padrao
  configurado, falha. Tratar excecao e mostrar mensagem.
- run_local_server precisa conseguir abrir uma porta local; firewall corporativo
  muito restrito pode bloquear. Em maquina pessoal, sem problema.
- Client secret do Desktop e aceitavel no .env, mas nunca commitar.
- Nao guardamos o token do Google: usamos apenas para identificar o usuario no
  momento do login. Se um dia precisar de Gmail/Calendar, ai sim guardariamos
  refresh_token (fora do escopo agora).
